- 真实 thermal 前向对临时中心/热头产生有限非零梯度，而原生 RGB/opacity/shape 参数及已有 `.grad` 不变；普通 RGB graph 不向热头反传。

- 真实 source 搜索在首次 witness 渲染前结束；没有读取 witness 后再返回 source 调整候选。
- manifest→原生 checkpoint→优化提交→保存→恢复审计的 CLI 小型往返。

测试没有证明任意 CUDA 场景下都无数值问题，也没有验证多百万高斯峰值显存、吞吐或完整训练收敛。

## 发现并推动修复的问题

| 问题 | 修复及复核 |
|---|---|
| `reindex` 在发现 foreign optimizer parameter 前已经替换模型参数，异常会留下半更新拓扑 | 先检查 optimizer 所有权，再更新模型；原子拒绝与有效 Adam 行映射均有回归。 |
| 有限 float64 raw/reference scale 转 float32 后可能变成 inf | 转换后的数值再次检查；`1e100` 溢出回归通过。 |
| v1 拒绝时 `GateDecision` 默认零值覆盖实际候选 source gain，影响失败解释 | 保留候选 gain 独立字段；旧 probe 的零字段不能解释为实际没有下降，应查看候选 gain 数组。 |
| v2 绕开旧 gate 函数，同时绕开阈值有限性、最小 witness 数和物理时间戳校验 | 通用验证移到两种 engine 共用的构造与 preflight；NaN RGB 容差、witness 数不足和 NaN 时间戳回归通过。 |
| 全局 RGB mask 可能只约束与热变化无关的亮背景 | v2 以 changed Gaussians 的真实 alpha 合成贡献构造局部支撑，覆盖旧/新投影；无关顶部亮区负例被拒绝。此修复提供模型内可见支撑，仍不是跨谱真实材质/遮挡标定。 |

## 原生有限差分：保留失败事实及适用范围

最初完整图像测试使用 `eps=1e-4`：几何解析导数为 **1.5258721**，数值导数 **1.6254187**，约相差 6.5%，超过原 5% 容差。审查没有直接放宽容差。

进一步检查得到：

1. 完整图像在 `eps=1e-3`、`3e-3` 的数值导数分别约 **1.55413**、**1.55097**，与解析值差约 1.9% 和 1.6%；热头导数在同范围稳定。
2. 同一高斯在 `±1e-4` 时，有一个像素的合成贡献从 **0** 跳至 **0.00393189**。原生配置的 alpha 阈值为 **1/255 ≈ 0.00392157**，前向代码会跳过低于阈值的贡献。这是实际观察到的离散支持变化。
3. 固定该高斯 baseline contribution >0.05 的 141 个内部像素，重新计算损失和梯度：解析值 **29.57903**，`eps=1e-4` 数值值 **29.58298**，相差约 0.013%。遮罩在比较期间固定，没有根据正负候选重新选择。

最终测试保留两种完整图像有限步尺度的 5% 检查，并新增固定内部区域小步长的 1% 检查。原生 alpha 截断会使整体前向函数分段变化，不能宣称该 backend 处处光滑、完整图像梯度在任意极小步长都精确。以上证据支持本次差异与边界跳变有关，但不构成对全部原生 backward 的完整正确性证明。

v2 使用实际前向损失选择和检验候选，能降低错误局部方向直接被提交的风险；它不能消除光栅化离散性。

## 为什么接受 v2 调整

检查 `output/thermal_supervision/v1_probe/results.json`：seed 0–2 的 geometry/mixed 场景均 0 次提交，有正 source 几何下降，但被拟合匹配约束拒绝。热外观已经较好，或位置/轮廓错误无法靠单纯改变热亮度解释时，要求 A 同时取得近似下降会拒绝正确 G。

v2 在 source 上用固定预算先拟合热外观，冻结该结果，再从残差求 G；候选必须同时改善其他训练视角相对于 profiled A 和 live 原状态的误差，并通过局部/全局/固定锚点 RGB 保护。接受时提交实际检验过的 head+delta 组合，避免“验证一种状态、提交另一种状态”。无持久 thermal optimizer 也避免了临时 head 与旧 Adam 动量不一致的问题。

检查现有报告发现：

| 报告 | 观察到的事实 |
|---|---|
| `v2_probe`，seed 0–2 | geometry/mixed 均有提交且中心误差及独立测试视角误差改善；appearance/unchanged 无更新。 |
| `v2_confirmation`，seed 10–14 | 10 个 geometry/mixed 条件全部改善；10 个 appearance/unchanged 条件均无更新。 |
| `v2_stress`，seed 10–12 | 三个常数热头 cold-start 条件均改善；三个仅热图发生位置变化、RGB 几何正确的条件均被拒绝。 |

这些结果足以支持“v2 解决当前 v1 原型在该可控问题上的停滞”。但还有一个算法归因限制：v1 先贪心选择 source 下降最大的 G，再寻找相匹配 A，没有搜索全部可匹配 G/A 对。较小 G 有时可能通过匹配。因此不能宣称所有 source-fit-matching 方法均无效；后续仍应加入配对搜索 v1、固定 thermal loss、普通交替优化及去掉 witness 的对照。

## 合成证据不能支持的结论

当前 fixture 只有 20 个高斯，真值和求解使用同一个原生渲染器；拓扑、opacity、shape 和 RGB 外观均接近理想已知，主要几何扰动是所有中心统一沿 x 平移。暗化仅用 gain，未模拟真实 RAW 噪声、坏点、局部 AGC、跨谱反射或未建模标定误差；模糊是已知静态相机曝光采样。新增 seed 改变随机颜色/热值/深度，但没有引入独立真实场景分布。

由此带来的限制：

- 很高的合成 PSNR 增量反映理想、小尺度已知表示中的误差修复，不是可承诺的真实数据增益。零误差时报告中的 150 dB 来自 MSE floor，是显示约定。
- `thermal_only_shift` 是几何一致 RGB 对错误热几何的拒绝检查，不等同于一般热传导、局部移动热斑、未知温度变化或复杂热反射问题。
- 一次或数次成功提交不能证明长期 head/geometry 交替优化稳定；局部支撑及锚点在更多遮挡、拓扑变化和 mask 更新下仍需审计。
- 当前代码调用真实 4D backend，但 CLI 明确限制静态 manifest；不能据此声称已完成动态 4D 热监督或 N1b v4 残差兼容。拒绝含动态残差的 checkpoint 是正确的边界处理。

## 后续仍需保留的条件

1. 在真实、合格的 RGB-T 多视角数据上验证 K/外参/线性响应、曝光、有效域及初始化来源；witness 只能是训练观测。二维配对数据无法补足这些条件。
2. 进行有/无 thermal、简单联合损失、配对搜索 v1、普通外观/几何交替和相同时间预算对照；本轮没有隔离 v2 相对这些便宜方法的收益。
3. 加入真实噪声、非统一几何扰动、热外观变化、错误标定和遮挡压力测试；独立深度/已知几何指标与 RGB 指标分别报告。
4. 在较大场景实测 source profiling、失败候选和局部 support 渲染的全部成本；不要从参数量或小 fixture 时间推导低开销。
5. 目前并非完整 FasterGS4D Trainer callback 集成。若要允许 RGB 参数继续更新、扩展到动态或改变拓扑，应重新验证状态版本、reference scale、局部支撑、anchor 和 optimizer 所有权。

本轮没有发现修复后仍阻塞这份静态实验适配器交付的已复现实现漏洞。建议交付代码、测试与完整限制说明，再以真实数据评估决定是否继续扩大算法主张。
