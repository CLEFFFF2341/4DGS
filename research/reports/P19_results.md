# P19 按实际资源成本选择结果

状态：`ADVANCED_STAGE1`。场景 `cut_roasted_beef`，0FT，开发视角 `{cam01, cam02}` × `T24` 共 48 帧。所有选择均为确定性；种子 0/1/2 的 ID 不变性通过后每行只评测一次。R0、R1 分属 byte 与 tile 两条预算赛道，不能按 PSNR 跨赛道直接排名。

## 结果

| 行 | 预算 | 点数（静态 / 动态） | bundle bytes | tile cost | PSNR | LPIPS-Alex | worst-10% drop | wall latency |
|---|---|---:|---:|---:|---:|---:|---:|---:|
| R0 `E/byte` | 50% byte | 136,920（108,338 / 28,582） | 65,288,944 | 1,157,064.90 | **27.386088** | **0.072712** | **11.425229 dB** | 7.853 ms |
| C0 纯 E | 同 byte cap | 121,887（89,276 / 32,611） | 65,289,098 | 1,032,398.19 | 27.192001 | 0.075848 | 11.685195 dB | 6.933 ms |
| R1 `E/tile` | 50% tile | 161,630（118,884 / 42,746） | 86,075,224 | 816,778.65 | **34.178304** | **0.052471** | **2.128688 dB** | **5.540 ms** |
| C1 纯 E | 同 tile cap | 107,601（77,410 / 30,191） | 59,040,450 | 816,778.65 | 32.835330 | 0.062941 | 3.507184 dB | 5.990 ms |
| R2 / P02 | 50% 点数 | 124,447（92,516 / 31,931） | 65,295,178 | 1,055,766.00 | 27.250421 | 0.075145 | 11.675420 dB | 7.095 ms |

R0 在实际 bundle 不超过同一 cap 的条件下比 C0 高 **0.194087 dB**，LPIPS 好 **0.003137**，尾部好 0.259966 dB；比 P02 高 0.135667 dB、少 6,234 B。它通过同字节质量门槛。但 C0 的 tile cost 低 10.77%、延迟快 11.72%，所以 R0 只支持“byte-aware 在同字节下改善质量”，不是多资源同时支配。

R1 与 C1 的 tile cost 位级相同；R1 高 **1.342975 dB**，LPIPS 好 **0.010470**，尾部好 1.378496 dB，实际 wall latency 还低 7.51%。相对同输入的全模型 10.703 ms 基线，R1 延迟降低约 48.24%，因此通过 tile 赛道的质量和实际速度门槛。但 R1 的 bundle 比 C1 大 27.0 MB，不能把它称为同字节胜利。

P12 的 global top-K 在 66.471 MB 下仍只有 27.249270 dB；P19-R0 以更小 bundle 达到 27.386088 dB。该差异不仅是静动态比例变化：R0 同时使用逐 kind payload 成本进行点级排序，但结果仍只证明这个固定代理在 S0 有效。

## 正确性与资源审计

- 不同 cost toy 会改变最优扫描集合；`cost=0,E>0` 优先、`0/0` 末尾且不会死循环；固定 header 大于 cap 会直接报不可行。
- K1 首个时间片重新执行四个 C4 视角后，逐点 CUDA `tiles_touched` 与缓存完全一致，最大误差 0、总和均为 6,559,251。
- R0 实际 bundle 为 65,288,944 B，低于 65,289,122 B cap 178 B；C0 也严格低于 cap。R1/C1 的选中 tile cost 均为 816,778.645833，低于 cap 0.005208。
- R1 按规则在所有正 ratio 项之后纳入 14,156 个 `0 cost / 0 E` 点；它们不改变注册 tile 预算，但增加点数与 bundle，已计入所有资源结果。
- R2 ID 与冻结 P02 位级一致；所有行全保留 identity、stable ID、bundle save/load、两帧 smoke 和三块 GPU timing 通过。

## 结论与限制

R0 和 R1 作为不同资源赛道候选进入阶段一待排序集合。ratio greedy 只优化加性 P02.E/参考 cost，不保证非线性 alpha 合成的全局最优；tile 代理来自统计视角/时间和低分辨率投影，真实 V 延迟是必要的独立验证。当前证据来自一个预训练已见开发相机的场景，不是跨场景泛化或统计显著性证明。
