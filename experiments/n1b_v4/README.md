# N1b v4：原生增密后的局部时间残差

当前是实验候选，**尚不能宣称稳定超过完整 FasterGS 原生基线**。
旧版全局仿射场在完整 Coffee seed 0 的 PSNR 为 -0.075604 dB；新结构
先在训练相机内部划分的验证集上筛选，不重复用官方测试集调参。

## 当前冻结的结构

前 15,000 步运行原生 FasterGS4D。增密结束后，每个高斯增加 3 个零初始化
加速度系数 a，学习率 0.05，继续至总计 30,000 步。保留原生损失及所有原生
参数的学习率。渲染输入中心增加：

```
q = clamp((t - tau) / sigma_t_ref, -3, 3)
delta_mu = sigma_xyz_conditional_ref * a * q^2
```

原生 CUDA 中的四维高斯条件均值项继续生效。新增项在自身中心时刻 tau 的
位移和一阶时间导数均为 0，只增加曲率。归一化尺度从共享检查点的四维协方差
计算并固定。参数、Adam 状态和参考尺度都随原生剪枝、排序同步变化。

这个候选不含时间颜色项，不增加 MSE 损失，也不延长训练步数。

选择曲率的原因：单个原生四维高斯的条件中心为
`mu_xyz + Sigma_xt / Sigma_tt * (t - tau)`，对时间是线性的；新增二次项提供
单个原生高斯不能直接吸收的轨迹曲率。旧全局场约 99.95% 的时间系数能量可由
常数与线性部分解释，因此它增加的有效非线性较少。后者只是参数诊断，不能
当作旧方法失败的因果证明。新方法仍需以冻结后的真实数据比较为准。

## 实验约束

完整预声明、失败条件和下一阶段规则见 [PROTOCOL.md](PROTOCOL.md)。
内部数据为官方 AREA 缩放 0.125、每十帧采样，450 张训练图，cam08 的 30 张
图用于筛选，cam16 的 30 张图留作选型后的检验；官方测试 cam00 不参与开发。
原始点云在相机划分之前已存在，所以初始化不具备相机独立性。

保存原生 15k 检查点时，同时保留优化器、采样序列、游标与随机状态。各分支
从同一状态继续，执行相同样本序列。CUDA 浮点原子运算仍有微小非确定性，
不能将这样的配对描述为逐位确定。

seed 0 主验证的已完成初始结果：

分支列表保存在 [results/development.json](results/development.json)。

## 运行

Windows 使用 `.conda/nerficg/python.exe`，并将该环境的 `Library/bin` 加到 PATH。

```
python -m experiments.n1b_v4.sweep --seed 0
python -m experiments.n1b_v4.round2 --seed 0
python -m experiments.n1b_v4.confirm --seed 1 --kind accel --accel-lr .05
python -m experiments.n1b_v4.evaluate_saved --run output/n1b_v4/dev_s1_candidate --secondary
python -m experiments.n1b_v4.summarize
```

只有通过内部复现和预留相机检验后，才按协议使用 `confirm --full` 做完整分辨率
与官方 300 测试图的多种子对照。失败或未完成的输出目录不会自动覆盖。

模型保存在实验目录的 `final.pt`，包含原生参数、新增系数及固定参考尺度；
通过 `evaluate_saved` 和 `ResidualRenderer` 加载、推理。原生 PLY 格式不包含
新增参数，不能用省略这些参数的导出模型代替本实验模型进行评分。

## 已知运行故障

- 首次原生续训在 30k 后写计时器时失败；修复仅初始化未执行的预训练回调计时元数据，
  不重新初始化模型或采样器。同一种子、检查点重跑，失败目录保留。
- 首次 accel_color 子进程在启动时发生 Windows access violation，日志为空、
  未创建实验目录；相同配置重试完成。
- 首次 accel_fast 在无更新渲染一致性检查处失败，未进行训练。原生 CUDA 重复
  渲染存在约 1e-6 RMSE 的数值变化；保留原检查阈值与失败目录后重跑通过。
  后续审计会在断言前写出数值，避免丢失失败证据。

单元检查已验证剪枝/排序后的参数和优化器对应关系，以及中心时刻位移和导数
不变；实际分支还检查零初始化渲染一致性和训练后所有参数有限。
